Store Task Planning & Shift Scheduling

Daily restock, price label and planogram reset tasks for the 10 Walmart stores in the public M5 dataset, built with SQL on DuckDB from real item demand and real week over week shelf price changes, then scheduled across associate shifts with an OR-Tools CP-SAT model and compared with first come first served. A LangGraph agent turns a manager's request into the same tool calls. Window: 2016-04-25 to 2016-05-22, 280 store days. Store layout, shelf capacity, task durations and shifts are synthetic (seeded). Source on GitHub.

Policy summary

CP-SAT finishes the most high priority work, but the priority greedy rule loses the fewest units: the CP-SAT objective counts tasks, not units at risk, and favours short tasks. CP-SAT also walks slightly more per task. Both are reported, not tuned away.

Model ablation

One overloaded day per store, 3 associates, 10 s each.

The exact routing model (a circuit per associate) is too large at ~130 tasks; a 15 minute start grid makes it smaller but wastes time on 8 to 20 minute tasks.

Planning agent

Success = right tools, exact arguments, task set equal to the gold run, numbers in answers, no tool calls on refusals. v2 fixes came from the v1 failure review; the 19 request holdout was written before any v2 run.
